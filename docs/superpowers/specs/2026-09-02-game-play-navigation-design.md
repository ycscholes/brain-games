# 所有游戏游玩页返回导航设计

## 目标

所有游戏进入游玩状态后，页面顶部的返回操作都返回当前游戏自己的开始/难度选择页，而不是返回小程序首页。返回游玩页时必须继续沿用该游戏已有的中途退出结算、闯关衔接和资源清理逻辑。

## 方案

游戏页隐藏微信原生导航栏，新增共享的自定义游玩导航栏组件。组件只负责展示标题和触发返回回调，不持有游戏状态；各游戏页面继续负责自己的 `backToStart`、计分结算、定时器清理和状态重置。游玩状态显示组件，开始状态和结算状态不显示组件。

每个游戏页配置 `navigationStyle: "custom"`，避免用户触发原生返回而离开到小程序首页。自定义返回按钮使用触摸安全的点击区域和页面当前游戏标题，样式遵循项目现有游戏页视觉语言。

## 接入范围

覆盖所有可从首页或全部游戏目录进入的独立游戏页；不修改小程序首页、全部游戏目录、宠物、设置、训练记录和闯关页的页面返回语义。对已有游玩中返回控件的游戏，统一替换为共享组件，避免重复导航样式。

## 行为与边界

- 点击返回只回到当前游戏的开始/难度选择状态，不调用 `reLaunch` 到 `/pages/index/index`。
- 页面已有中断记录逻辑必须在返回前执行；若当前页面处于闯关模式，继续由现有闯关流程决定后续跳转。
- 返回时清理该游戏已有的计时器、动画帧、临时棋盘/题目和选择状态。
- 非游玩状态不显示游玩返回栏，现有“再来一局”“返回开始页”等结算操作保持不变。

## 验证

新增共享导航组件的回调行为测试，并为代表性游戏验证游玩态显示、点击回调和页面配置。运行相关单元测试、完整测试、类型检查、Lint、微信小程序构建及 `git diff --check`。
