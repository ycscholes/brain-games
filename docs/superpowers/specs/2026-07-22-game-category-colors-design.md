# 游戏分组配色设计

## 目标

让用户在首页和“全部游戏”页中，能通过一致、清爽的颜色快速识别游戏所属分组，同时维持现有游戏名称、能力说明、难度和成绩信息的阅读优先级。

## 范围

- 覆盖现有五个游戏分组：计算与数理、记忆与反应、推理、语言、综合挑战。
- 覆盖首页和“全部游戏”页复用的分组列表与游戏卡片。
- 不改变游戏分组、排序、搜索、导航、分数或奖励逻辑。

## 视觉方案

采用“顶部色条 + 柔和光斑”方案：

| 分组 | 色彩 | 用途 |
| --- | --- | --- |
| 计算与数理 | 天蓝 | 标题、数量胶囊、卡片顶部横条与浅色光斑 |
| 记忆与反应 | 紫色 | 标题、数量胶囊、卡片顶部横条与浅色光斑 |
| 推理 | 薄荷绿 | 标题、数量胶囊、卡片顶部横条与浅色光斑 |
| 语言 | 琥珀黄 | 标题、数量胶囊、卡片顶部横条与浅色光斑 |
| 综合挑战 | 珊瑚红 | 标题、数量胶囊、卡片顶部横条与浅色光斑 |

卡片顶部横条为 6px。右上角使用低透明度的同色圆形光斑，作为背景装饰；标题、能力、难度和成绩文本保持既有中性色。各游戏既有的细节背景仍保留，分组色只提供跨卡片的一致识别层。

## 实现边界

分组列表的容器会带上由既有 `category` 值生成的语义类名。共享 SCSS 在该容器上定义分组色彩变量，并由标题、数量胶囊与卡片装饰消费这些变量。首页和“全部游戏”页沿用相同的渲染结构，因此无需复制颜色表或引入新的数据字段。

## 验证

- 确认首页和“全部游戏”页的五个分组均传递正确的语义类名。
- 确认搜索过滤后保留的分组仍应用正确颜色。
- 运行相关单元测试、类型检查、lint、微信小程序构建、`git diff --check` 和密钥检查。
