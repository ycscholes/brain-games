# 车阵突围困难模式认证题库设计

## 目标

把困难模式从“十辆车且最短解不少于 5 次”的随机题面，升级为熟练玩家约 2–3 分钟完成的稳定深度题面。难度来自多层阻塞、有限的正确入口和具有迷惑性的合法分支，不依赖继续增加棋盘或车辆数量。

普通模式、车辆移动规则、目标车、提示扣分、游戏分上限、共享宠物积分管线和游戏大闯关接口保持不变。

## 当前问题

当前困难模式在运行时从一个固定已解布局反向随机移动，再用 BFS 只检查车辆数量和最短解下限。随机移动可能互相抵消，也没有衡量最优解涉及多少辆车、是否存在连续解锁关系、第一步是否过于明显。因此十辆车和五步最短解仍可能形成线性、容易识别的题面。

运行时还要反复生成并求解候选题。在微信小程序设备上继续提高搜索深度，会同时增加开局延迟和提示延迟，难以稳定控制。

## 选定架构

采用“离线生成、离线认证、运行时选题”的混合架构：

1. 开发阶段用确定性种子批量生成十车候选题。
2. 生成过程使用无立即撤销、无重复状态的反向随机游走，并从多个已解基础布局出发，减少同构题。
3. 每个候选题由 BFS 求出最短解，并由独立质量分析器计算复杂度指标。
4. 只有全部指标达标且与已选题不重复的候选题才进入生成题库。
5. 运行时困难模式只从认证题库随机选择，不再执行批量生成搜索。
6. 玩家请求提示时仍从当前局面求解，因此偏离认证最优路径后仍能获得有效提示。

生成器、质量分析器和运行时移动规则复用同一套 `TrafficEscapePuzzle`、移动校验、状态键与 BFS 语义，避免离线认证和游戏实际行为不一致。

## 困难题认证标准

每道困难题必须同时满足：

| 指标 | 要求 | 作用 |
|---|---:|---|
| 棋盘 | `6 x 6` | 保持现有移动端布局 |
| 车辆数量 | 恰好 10 辆 | 保持当前困难模式密度 |
| 最短解 | 8–12 次调度 | 对齐熟练玩家 2–3 分钟目标 |
| 最优解涉及车辆 | 至少 5 辆 | 避免只挪两三辆车的直线题 |
| 红车首次移动 | 最优解最后一步 | 确保先完成完整解锁链 |
| 阻塞依赖深度 | 至少 3 层 | 保证“先为另一辆车腾位”的多层推理 |
| 初始合法调度 | 至少 4 个 | 提供需要判断的分支 |
| 最优首步 | 1–2 个 | 避免答案入口过多、试探成本过低 |
| BFS 访问状态 | 不超过 12,000 | 控制偏离路径后的提示成本 |

一次调度继续表示同一辆车沿朝向移动任意合法距离，而不是每移动一格计一步。

“阻塞依赖深度”按最短解回放计算：如果后续关键调度在前一状态不可执行，而执行当前调度后变为可执行，则建立一条依赖边；通向红车出场调度的最长依赖链至少包含三辆非目标车。该定义可由纯逻辑测试重复计算，不依赖人工标注。

## 题库规模与生成

首版保存 36 道认证困难题。按当前数据结构估算，题面、解法与认证元数据只增加几十 KB 源码，不引入图片或远程资源，对微信小程序包体影响可控。

离线生成器遍历固定种子范围，并从至少四个十车已解模板生成候选。每次反向游走记录状态键，拒绝立即执行上一调度的反向操作，也拒绝回到已访问状态。候选通过认证后，以忽略车辆颜色、外观和 ID 的几何状态键去重。

生成命令必须具备确定性：相同代码和种子范围应得到字节一致的题库文件。生成不足 36 道时命令失败，不覆盖现有题库。

## 运行时行为

- 普通模式继续使用现有生成逻辑和难度标准。
- 困难模式从 36 道认证题中选择一题，并在进入游戏时随机分配车辆外观。
- 题库内保存认证时的最短解，作为初始局面的答案与质量证明。
- 玩家偏离初始最短解后，提示按钮对当前状态执行 BFS；同一局面求解结果使用有界缓存复用。
- 如果当前局面无解，提示返回空并沿用现有反馈，不自动重置或替玩家移动。

困难模式的速度奖励阈值同步适配 2–3 分钟目标：150 秒以内获得最高速度奖励，210 秒以内获得中档速度奖励；基础分、移动效率奖励、每次提示扣 4 分、游戏分上限 50 和困难宠物积分倍率保持不变。

## 文件边界

- `src/pages/traffic-escape/gameLogic.ts`：运行时移动、求解、提示、计分和难度选题。
- `src/pages/traffic-escape/puzzleGenerator.ts`：仅供离线工具使用的模板、反向游走和候选生成。
- `src/pages/traffic-escape/puzzleQuality.ts`：复杂度分析、认证规则和几何去重键。
- `src/pages/traffic-escape/hardPuzzles.generated.ts`：自动生成的 36 道认证困难题，不手工编辑。
- `scripts/generate-traffic-escape-hard-puzzles.ts`：批量生成、认证、排序及原子写入题库。
- `scripts/generate-traffic-escape-hard-puzzles.sh`：使用项目 TypeScript 编译器在临时目录执行生成器，不新增运行时依赖。
- `tests/unit/trafficEscapePuzzleQuality.test.ts`：质量指标和认证器单元测试。
- `tests/unit/trafficEscapeGameLogic.test.ts`：题库完整性、运行时选题、提示与计分回归测试。

## 失败处理

- 离线候选不足、存在重复题、认证指标不达标或输出非确定性时，生成命令以非零状态退出，且不改写已提交题库。
- 编译期测试要求生成题库数量严格为 36，任意题目不合格都会阻止提交。
- 运行时不依赖生成器，因此离线生成失败不会影响已发布版本。
- 提示搜索达到状态上限仍无解时返回空，不阻塞页面，也不发放或扣除积分。

## 验证与验收

自动化验证必须证明：

1. 36 道困难题全部为 6 x 6、十辆车、可解且满足所有认证指标。
2. 相同种子范围连续生成两次得到相同内容。
3. 困难模式不会退回旧的六车或未认证题池。
4. 从每道题的若干合法偏离状态请求提示，返回的调度合法且仍可通关。
5. 普通模式、移动碰撞、外观分配、训练记录和积分管线保持原行为。
6. 定向测试、全量测试、类型检查、lint、微信小程序构建、密钥检查和 `git diff --check` 全部通过。

设备验收在微信开发者工具和至少一台真机各试玩多道困难题，记录熟练玩家完成时长中位数。目标中位数为 120–180 秒；如果明显低于 120 秒，优先提高依赖深度或最短解下限，而不是增加车辆；如果明显高于 180 秒，优先放宽最优首步或最短解上限。
