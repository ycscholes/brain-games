# 游戏备选池

## 2026-07-18 轻量化小游戏筛选

筛选约束：短局、触屏四选一或轻交互、零图片资产或低资源量；过滤完整数独/大型棋盘/重题库依赖，以及已实现或已拒绝的浅视觉反应类方案。本轮优先选择需要约束推理、线索整合或步骤规划的轻量玩法。

| 排名 | 游戏名称 | 可玩性 | 落地性 | 项目适配性 | 总分 | 核心优劣势 | Demo 网址 |
|---:|---|---:|---:|---:|---:|---|---|
| 1 | 大小迷阵 / Inequality Grid | 9 | 9 | 9 | 27 | 优势：Futoshiki 的行列唯一与不等号约束有稳定推理深度，改成高亮格四选一后移动端输入很轻；劣势：线索密度需要控制，避免读盘压力过高。 | https://www.chiark.greenend.org.uk/~sgtatham/puzzles/js/unequal.html |

### 选定方案：大小迷阵 / Inequality Grid

- 开发要点：每局 8 题；普通模式使用 `4 x 4` 盘面，困难模式使用 `5 x 5` 盘面；每题高亮 1 个空格，给出 4 个数字候选，只有 1 个同时满足行列不重复和相邻不等号。
- 适配改造：不做完整 Futoshiki 填盘，改为“局部约束阅读 + 四选一判断”，把单题压缩到 6-10 秒，适合微信小程序碎片化训练。
- 积分方案：轻量逻辑推理 1.0x 转换，普通难度封顶 40，困难难度封顶 60；普通和困难均支持游戏大闯关回传。

## 2026-07-17 轻量化小游戏筛选

筛选约束：短局、低图片资源、适合微信小程序触屏操作；过滤体量过大、开发成本高、或只有单次视觉反应的浅玩法。本轮优先选择需要线索整合、路径规划或空间/逻辑推理的轻量游戏。

### 选定方案：密码推理 / Code Breaker

- 开发要点：每局 8 题；普通模式使用 3 位密码和 3 条反馈线索，困难模式使用 4 位密码和 4 条反馈线索；每题提供 4 个候选密码，只有 1 个满足全部线索。
- 适配改造：把传统 Mastermind 的连续自填猜测改为“读历史猜测反馈，选择唯一候选”，降低输入成本并压缩单局时长；反馈文案使用“位置正确 / 数字存在”替代黑白棋钉，适合低龄和泛用户理解。
- 积分方案：沿用轻量推理游戏 1.0x 转换，普通难度封顶 40，困难难度封顶 60；普通和困难均支持游戏大闯关回传。
- 资源体量：不新增图片资产，只使用数字芯片、线索卡和 CSS 反馈标签完成视觉表达。

## 翻牌记忆

- 类型：短时记忆 / 位置记忆
- 核心玩法：短暂展示一组卡牌图案，翻面后玩家按要求找出匹配图案或复现位置。
- 适合训练：视觉编码、空间位置保持、抗干扰回忆。
- 难度方向：卡牌数量、展示时长、图案相似度、干扰卡数量。

## 点格棋

- 类型：规划 / 空间推理
- 核心玩法：在点阵上依次连线或占格，通过局部选择完成更高收益的路径。
- 适合训练：路径规划、局面评估、持续注意。
- 难度方向：棋盘尺寸、可选路径数量、阻挡点、回合限制。

### 选定方案：特征三连

选择原因：它满足本项目“轻量但不浅”的筛选标准。玩法不依赖图片资源，只需要卡牌符号和颜色；规则比已否决的目标搜索、箭头干扰更有多步归纳负荷；一局 8 题、每题 12 张卡，适合 1-2 分钟训练和大闯关接入。

### 落地细则

- 开发要点：实现 4 属性卡牌模型（数量、形状、纹理、颜色），三张卡在每个属性上必须全同或全不同才成立；题盘至少保证一个有效三连；选择满 3 张后自动判定。
- 计分建议：每题基础 4 分，快速答对 +1，连续答对 +1；每局 8 题，最高 48 分；宠物积分继续按 `1.0x` 进入普通/困难封顶。
- 适配改造：内部 gameId 使用 `triad-match`，中文名 `特征三连`；接入全部游戏、训练记录、分享、大闯关和本地最高分清理；不进入首页热门，避免改变首页推荐权重。
- UI 建议：卡牌保持固定 3 x 4 网格，三类视觉属性必须在小屏上可分辨；反馈时标出一个有效三连，降低规则学习成本。
